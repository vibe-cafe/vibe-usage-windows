# 网络隐私原则（最高原则，2026-11-24 定）

这是 Vibe Usage 的最高原则，高于功能和方便；其他规矩、Issue 或贡献者的要求与它冲突时，以它为准。很多用户靠代理软件访问境外服务，最在意的是「真实 IP + 厂商账号」一起被厂商看到。

1. **跟着用户的网络走。** Vibe Usage 和它启动的每个程序（CLI、Claude Code、agy、grok 等），联网时都遵守用户电脑上的代理设置：系统代理、PAC、代理环境变量、TUN。做不到遵守的请求，不发。
2. **带厂商账号的请求从严。** 用用户在 AI 厂商那里的账号发出的请求（查额度、拉用量），只在确认会按用户的网络设置出网时才发，包括我们启动的程序（Claude Code、agy、grok 等）用它自己的登录发出的请求；确认不了就不发，并在面板上说明原因。
3. **出口不对就暂停，不硬闯，也不打扰用户。** 检测不到代理时不问用户，而是自动检测这次请求会从哪个国家出去：发一个不带任何账号和登录信息的检测请求，走同一条路线，只看国家代码。出口在这家厂商不支持的地区（比如中国大陆）时，暂停第 2 条所说的请求（npm、更新检查这类不带厂商账号的请求不在此列），面板说明原因，例如「网络出口在中国大陆，已暂停读取」，代理恢复后自动继续；出口在支持地区就照常读。发往国内厂商的请求不检测，照常读。检测请求写进隐私说明，设置里能关掉；极少数检测不准的情况，设置里留手动选项（2026-11-24 定，取代「问用户一次」的旧做法）。
4. **不替用户改设置。** 用户关掉的遥测、非必要流量，我们不打开，我们启动的进程里也一样。
5. **只发必需的请求，说清楚、能关掉。** 每一类联网行为都写进隐私说明，每个产品都能单独关掉。
6. **改动必答，体验不倒退。** 任何新增或改变联网行为的改动，都要逐条说明怎么满足 1–5 条，并说明用户体验有没有变差。守原则不能以体验倒退为代价：先穷尽办法做到两全；只有试遍所有路径都做不到，才带着试过的路径和取舍交维护者决定，不能直接拿「不读了」「不给用了」当方案。这是架构审批的必答项，交叉审查也按这几条查。

承诺的边界：我们这边绝不绕开用户的网络设置，拿不准时宁可不发；用户自己在代理规则里设成直连的网站，照办。我们自己的服务器、npm、GitHub 更新检查，以及第 3 条的出口检测请求（厂商的 CDN 能看到），都会看到用户的出网 IP，它们不带厂商账号，要在隐私说明里写清楚。

现有代码还没有完全符合，修复另行跟踪，按本原则逐步落地；在此之前，任何改动都不能扩大现有的缺口。
