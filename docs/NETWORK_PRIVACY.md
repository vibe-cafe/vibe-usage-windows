# 网络隐私原则（最高原则，2026-11-24 定）

这是 Vibe Usage 的最高原则，高于功能和方便；其他规矩、Issue 或贡献者的要求与它冲突时，以它为准。很多用户靠代理软件访问境外服务，最在意的是「真实 IP + 厂商账号」一起被厂商看到。

1. **跟着用户的网络走。** Vibe Usage 和它启动的每个程序（CLI、Claude Code、agy、grok 等），联网时都遵守用户电脑上的代理设置：系统代理、PAC、代理环境变量、TUN。做不到遵守的请求，不发。
2. **带厂商账号的请求从严。** 用用户在 AI 厂商那里的账号发出的请求（查额度、拉用量），只在确认会按用户的网络设置出网时才发，包括我们启动的程序（Claude Code、agy、grok 等）用它自己的登录发出的请求；确认不了就不发，并在面板上说明原因。
3. **代理没开时提醒，不硬闯。** 用户说过自己靠代理上网、现在却检测不到代理时，暂停第 2 条所说的请求（npm、更新检查这类不带厂商账号的请求不在此列），面板提示未检测到代理、已暂停读取，代理恢复后自动继续。是否靠代理，在第一次检测不到代理时问用户一次并记住，不靠猜；回答不需要代理的用户照常直连。
4. **不替用户改设置。** 用户关掉的遥测、非必要流量，我们不打开，我们启动的进程里也一样。
5. **只发必需的请求，说清楚、能关掉。** 每一类联网行为都写进隐私说明，每个产品都能单独关掉。
6. **改动必答。** 任何新增或改变联网行为的改动，都要逐条说明怎么满足 1–5 条，这是架构审批的必答项，交叉审查也按这几条查。

承诺的边界：我们这边绝不绕开用户的网络设置，拿不准时宁可不发；用户自己在代理规则里设成直连的网站，照办。我们自己的服务器、npm、GitHub 更新检查会看到用户的出网 IP，它们不带厂商账号，要在隐私说明里写清楚。

现有代码还没有完全符合，修复另行跟踪，按本原则逐步落地；在此之前，任何改动都不能扩大现有的缺口。
